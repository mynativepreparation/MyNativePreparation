## Goal
A new user gets a 12-word key, optionally enters name/email/phone, reads an honest privacy note, and lands on Home. A returning user (new device, cleared browser)
pastes the 12 words and lands on Home. All personal data and progress in the local database is AES-256-GCM encrypted with a key derived from the 12 words.
The 12 words are never stored. Crypto code is pure and fully tested in `src/core/identity/`; screens live in `src/modules/onboarding/` and talk only through the wire.

## Design (made here, do not re-discuss)
- Words: `@scure/bip39`, English wordlist, `generateMnemonic(wordlist, 128)`. Input is normalized (trim, lower-case, NFKD, collapse whitespace) and must be exactly 12 words with a valid checksum.
  Validation returns a reason code (`wrong_count | unknown_word | bad_checksum`), never throws.
- Keys: `entropy = mnemonicToEntropy(...)` (16 bytes) -> `importKey('raw', entropy, 'HKDF', false, ['deriveKey'])` -> `deriveKey` HKDF-SHA-256, fixed salt `np/salt/v1`,
  `info` = `np/store/v1` (local store) or `np/backup/v1` (P12) -> AES-GCM 256, `extractable: false`. Overwrite the entropy bytes with zeros afterwards (best effort).
- Cipher: `encryptJson(key, value, aad)` / `decryptJson(key, envelope, aad)`; envelope `{ v: 1, iv: base64url(12 random bytes), ct: base64url }`; a NEW random IV for every call;
  AAD is a short string naming the table and row key (e.g. `attempts:42`) so a ciphertext cannot be moved to another row. Wrong key, wrong AAD or tampering -> a typed `DecryptError`, never a crash.
- Key check: the string `np-key-check-v1` is encrypted with the store key and saved in the `kv` table (`identity.check`). Login on a device WITH a check must decrypt it (else `wrong_key`).
  Login on a device with NO check (fresh device) accepts any valid 12 words and creates the check (data comes back later through the P12 backup file).
- Session: `src/core/identity/session.ts` holds the store key in memory. Owner rule (Q16): the 12 words are needed ONLY at Register, on a new device/cleared browser, and after an explicit Log out. Every other app open must not ask for them.
  So the store key is persisted (non-extractable CryptoKey in the Dexie table `session`, structured clone) and restored on open; if the fingerprint lock is on, restoring first needs the fingerprint (see below).
  `logOut()` deletes the persisted key, the wrapped key and the fingerprint credential record, and keeps the encrypted data on the device (logging in again with the same words opens it). While logged out, repo calls throw `LockedError`.
- Fingerprint lock (owner request 2026-11-18, optional, offered right after Register and later in Settings): uses WebAuthn with a platform authenticator (`authenticatorAttachment: "platform"`, `userVerification: "required"`), so the phone's fingerprint, face or screen lock is used; no biometric data ever reaches the app.
  Two honest levels, chosen at runtime: (1) PRF level, when the browser reports the WebAuthn `prf` extension: the store key is exported once (only while the words are in memory), wrapped (AES-GCM) with a key derived from the PRF output, and the wrapped copy replaces the plain persisted key, so unlocking REALLY needs the fingerprint;
  (2) gate level, when PRF is missing (e.g. Windows Hello on many PCs, some Android providers): the fingerprint check only guards the app opening and the UI says so ("protects the app screen, not the files"). PRF is treated as an enhancement, not a dependency (web search 2026-11-18: support is inconsistent).
  The 12 words ALWAYS unlock, whatever happens to the fingerprint credential (new phone, changed web address, reset lock). Needs HTTPS or localhost; the credential is tied to the site address, so a changed address means "use the 12 words once, then set up the fingerprint again". Inside the later Android APK wrapper (P13) WebAuthn may not work: a Capacitor biometric plugin will be decided there.
  Crypto logic sits behind a small interface (`PlatformAuth`) so tests use a fake; the real prompt is verified in the owner's browser check.
- PIN lock (owner request 2026-11-18, T12c; optional; offered after the fingerprint offer was skipped and later in Settings): for devices without a fingerprint reader. T12c shipped ONE app lock at a time (each refused while the other was on); T12d (owner decision 2026-11-19) lets BOTH be on: a good fingerprint opens the app alone, otherwise the PIN screen is the way in (the 12 words work from there). Exactly 6 digits, no straight runs (000000, 111111, 123456, 654321).
  The store key is wrapped (AES-GCM) with a key from PBKDF2-SHA-256 (600 000 rounds, random salt) and the wrapped copy replaces the plain saved key, so an app open needs the PIN (`/pin`). Honest wording: only 10^6 PINs exist, so someone who COPIES the data files could try them all offline; the PIN stops casual access, the 12 words are the real key.
  Five wrong PINs in a row (counter saved) remove the PIN lock and the 12 words are then needed once. The 12 words always unlock; Log out removes the lock with the rest of the session; a 12-word login never brings the plain key back while a PIN lock exists (`persistKey` rule, like the PRF level). Code: `core/identity/pin.ts`, screens `PinSetupScreen` / `PinScreen`, Settings `PinCard`.
- Local store v2 (Dexie): rows keep plain primary keys and index fields (course/block/test ids, `at`), and every other field moves into one encrypted `blob` envelope.
  `profile` = `{ id: "me", blob }`; `readProgress` = `{ courseId, blockId, blob }`; `attempts` = `{ id, courseId, testId, at, blob }`; `kv` stays plain for non-personal settings
  (`identity.check`, `identity.onboarded`). The v1 -> v2 upgrade deletes old rows (nothing released yet). All access stays inside `repo.ts`; its public function signatures do not change.
- The 12 words exist only: (1) in memory while the Register screen shows them, (2) in the Login text box while typing. Never in Dexie, localStorage, console, URL, wire events or error messages.
  Text fields use `autocomplete="off"`, `spellcheck={false}`, `autocapitalize="off"`.
- Privacy wording (replaces the owner's draft, same meaning but true): "This app has no server and no account. Your name, email, phone, progress and scores stay on this device, encrypted with a key made from your 12 words.
  The developer cannot read them and nobody can recover them if you lose the 12 words. The app does not back up anything by itself; you can save an encrypted backup file wherever you like.
  Course names, which lessons you opened and the dates of your tests are not hidden. Checking for updates and downloading courses contacts GitHub." Never write "military grade".
- Boundaries: `src/core/identity` may import `src/core/storage` and `src/core/content`, never `src/modules` or `src/app`. Screens never import `core/storage/db.ts`; they use `repo.ts` and `session.ts`.
- All visible text goes into `src/core/i18n/en.json`. Bundle: bip39 + English wordlist should add about 10 KB gzip; keep total JS <= 250 KB gzip (load the identity screens lazily if needed).
