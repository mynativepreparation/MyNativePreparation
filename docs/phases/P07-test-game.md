## Goal
Tapping the Test tile starts a friendly, game-like quiz: intro, one question at a time with 4 shuffled options, instant feedback with the optional explanation, a running score, a final result with 1-5 stars, a cheer message, confetti and sound. No timer, no negative marking (Q6). Finished games are saved with `addAttempt`; quitting halfway saves nothing.

## Design (decided here, do not re-discuss)
- Module `src/modules/test-game/` (own folder, registered like the reader). Pure logic in `engine.ts` (no React, no DOM, no sound) so it is fully testable; screens only draw the engine's state.
- Engine: `startGame(test, rng = Math.random)` picks `effectiveQuestionCount(questionsPerGame, questions.length)` questions (random subset and random order when the developer asks for fewer than exist), shuffles each question's 4 options with Fisher-Yates using `rng` and remembers where the correct one went. `answer(state, shownIndex)` records the choice once (a second tap does nothing), `next(state)` moves on, `finish` is reached after the last answer. State is immutable (each call returns a new object). Result = `correct`, `asked`, `percent`, `stars` (from `scoring.ts`, never recomputed elsewhere), plus the list of (question, chosen, correct) for the screen.
- Cheer messages by stars (en.json keys): 5 "Congratulations!", 4 "Great job!", 3 "Good effort!", 2 "Keep going!", 1 "Work harder!" (SPEC C5 asks for "Congratulations" / "Work harder"; the middle ones are ours).
- Screens: Intro (title, optional image, "N questions", Start), Question (progress "3 / 10" + bar, score so far, question text, 4 option buttons labelled A-D, after answering: correct option highlighted, wrong choice marked, the explanation card if present, `Next` / `See result`), Result (stars appear one by one, percent, "7 of 10 correct", message, Play again, Back to course, Report). Leaving halfway (Back button or browser back) asks "Leave the game? Your progress will be lost." (Stay / Leave).
- Feedback is never colour-only: icon (tick / cross) + text ("Correct!" / "Not quite") in an `aria-live="polite"` region. Options are real buttons, disabled after the answer; keys `1-4` or `A-D` choose, `Enter` goes on.
- Not available: unknown course, test `empty` / `invalid`, or zero effective questions -> the existing `NotAvailable` screen with Back (same as the reader).
- Sound (`sound.ts`): own Web Audio synth, no files: tap, correct (rising two notes), wrong (soft low note), result fanfare (longer for more stars). One `AudioContext`, created and `resume()`d on the Start tap (autoplay rule). Master volume is low. Mute toggle in the game header, remembered in `localStorage` key `np.test.sound` (all reads/writes in try/catch). If Web Audio is missing or throws, the game works silently.
- Confetti (`confetti.ts`): small own canvas particle burst, only for 3+ stars, ~2 s, removes its canvas when done or on unmount. Skipped completely when `prefers-reduced-motion: reduce` (stars then just fade in).
- Animation: CSS only with the motion tokens (`--np-motion-*`, `--np-ease`): question slide/fade, option press, correct pop, wrong shake, star pop. No animation library.
- Colours: new tokens for success, danger and star (light and dark) in the token file; CSS may use tokens only (styles.test.ts forbids hex colours and raw durations).
- Persisting: `addAttempt` exactly once when the last question is answered and the result opens (a test guards against a double save on re-render). The per-question choices live only in memory for the result screen.
- Boundaries: the module imports only `core/*`; it does not import other modules (it does not import `home`). Strings only in `src/core/i18n/en.json`. No new dependency.
- Tests: new tests go into NEW small files. Engine tests use a seeded rng. Sound tests use a fake `AudioContext`; the real sound is judged on the owner's phone.
