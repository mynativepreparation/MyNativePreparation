## Goal
The Report tile opens a screen that summarises the user's progress (courses opened, tests taken, best/last percent, stars) and creates a colourful, minimal PDF with REAL text (selectable, sharp at any zoom). The user can rename the file before saving; the file is saved or shared through what the device offers. Gujarati text (course titles, the user's name) must be shaped correctly: conjuncts, reph, rakaar, vowel signs.

## Library research (web search 2026-11-20; DECISIONS Q19 + Q20)
- A) `pdf-lib` 1.17.1 (MIT) + `@pdf-lib/fontkit`: about 174 KB gzip for pdf-lib (depscope); last release 2021-11 (maintenance risk). Allowed now that the budget is 600 KB.
- A2) `@cantoo/pdf-lib` (maintained fork, updated 2026-05, about 239 KB gzip, 7 dependencies): only if A fails or is judged too old.
- B) `pdfkit` (maintained, uses upstream `fontkit`): size not measured; needs a browser-ready build (standalone bundle or Vite with a blob stream).
- fontkit's `IndicShaper` lists Gujarati (script tags `gujr`, `gjr2`): promising, but real quality for conjuncts is unproven: the spike decides.
- `pdfnative` (no Gujarati among its 16 scripts) REJECTED. `jsPDF`, `pdfmake`: not tested.
- FALLBACK (if no library shapes Gujarati right): the browser shapes the text on a canvas with the bundled font, each A4 page becomes a JPEG inside a small own PDF writer (about 100 lines, no dependency); the text is then a picture (not selectable). Further fallbacks: browser print dialog on an HTML report; HarfBuzz WASM.

## Design (decided here, do not re-discuss)
- Module `src/modules/report/` (own folder, registered like `test-game`, auto-found by `app/boot.ts`); it imports only `core/*`, never another module. Strings only in `src/core/i18n/en.json` (the PDF labels too). Course/test titles and the user's name are passed through unchanged (they may be Gujarati).
- The layout never talks to a library. It draws on a tiny interface `PdfSurface` (`addPage`, `text`, `rect`, `line`, `path`, `measure`, `finish -> Uint8Array`); one adapter file per library (`pdf/pdfLibSurface.ts` or `pdf/pdfkitSurface.ts`, or `pdf/canvasSurface.ts` for the fallback). Swapping the library touches only the adapter.
- Heavy code is loaded with dynamic `import()` when the user taps Create PDF, so the first screen stays light (`js-size.ps1` still counts every chunk, budget 600 KB).
- Pure parts first: `reportData.ts` (model from repo data, no React, no PDF), `layout.ts` (model -> surface calls), `savePdf.ts` (save/share logic with injected `navigator`). The screen only wires them.
- "Course read" = the Overview or Content of the course was opened at least once (label says "opened", not "finished"). If `repo` has no such record, T4 adds one tiny function and ONE call in each reader screen (read their heads first). Reading percent would need scroll tracking: not in this phase.
- Scope switch on the screen: "All courses" (default, SPEC says courses plural) or "This course"; the current course is listed first.
- The PDF never contains email or phone; the name only if the user entered one.
- Look: A4 portrait, colourful header band, one card per course with progress bars and stars drawn as paths (not as text glyphs), page numbers; palette constants live in ONE file (`palette.ts`), taken from the app tokens, light colours only (it is a printed page). PDF metadata title set (Gujarati-safe).
- File name: default `NativePrep-report-YYYY-MM-DD`; the user edits it before saving; sanitised (`\ / : * ? " < > |` removed, trimmed, at most 80 characters, `.pdf` added once, Gujarati kept).
- Saving, feature-detected in this order, never assumed: `showSaveFilePicker` (suggested name) -> `navigator.share({files})` when `canShare` -> `<a download>`. User cancel (`AbortError`) is not an error. "App folder in device storage" (SPEC C6) belongs to the Android wrapper (P13, Capacitor Filesystem); the web version asks no file access until the user taps Save.
- Rendering never freezes the UI: a busy state with `aria-live` text; yield to the browser between pages.
- Empty state (nothing opened, no tests): friendly message and no PDF button.
- Font: Noto Sans Gujarati (OFL 1.1), regular + bold, in `public/fonts/` with its licence file; the PDF code fetches the bytes at runtime (fonts are not JS; the PWA precache grows a little, check at T10). The library embeds only the glyphs used (subset). Latin and Gujarati are separate font files (fontsource subsets): the layout splits a string into Latin and Gujarati runs (Gujarati block U+0A80-U+0AFF) and picks the font per run. The font files must also be in the PWA precache so the report works offline (check at T3 and T10).
- Dependencies: exact versions (`--save-exact`), newest stable at least 14 days old, MIT-compatible licence, recorded in DECISIONS; installed by a script, never by hand.
- Tests: new tests in NEW small files; unit tests use a FAKE `PdfSurface`; the real look is judged on the owner's PC and phone.
