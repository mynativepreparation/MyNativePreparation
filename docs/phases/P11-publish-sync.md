Status: ACTIVE (plan written 2026-11-23 at the end of P10). SPEC A3 (open source, update in place) and A4 (no own server, nobody reads user data). ## Goal
The owner presses **Publish** in the Admin window and a few minutes later every user sees the new or changed course WITHOUT updating the app; **Unpublish** takes it away. Courses the user already opened keep working offline. Nothing goes anywhere except GitHub (api.github.com from the Admin, static files from GitHub Pages).

## Risks and notes
- A fine-grained token must have Contents read and write on this ONE repo; extra editors (outside collaborators) are a later step (Q24).
- The Pages deploy needs 1-3 minutes: say so everywhere (T5, T9).
- Upload raw bytes (base64 blobs): `public/content/**` is `-text` in `.gitattributes`, so the SHA-256 in the manifest stays equal to the file.
- Rate limit about 5000 requests per hour with a token: one publish uses (changed files + about 6) requests; blobs at most 4 at a time.
- A Git Data commit made from the browser needs the token to reach `api.github.com` (CORS works for it, Q24 table); content is read back from Pages (CORS is open there).
